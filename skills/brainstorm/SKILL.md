## Activation Contract
Use for project-wide ideas and natural improvements. Work standalone in the selected project, independently of language or client. Do not turn an audit request into brainstorming.

## Hard Rules
- Write only inside the project's `brainstorming/`; never implement proposals or alter original code, configuration or data.
- Use the session language for replies and generated documents. Translate templates; preserve protocol IDs and human rationale.
- Read the shared contracts below before writing. Individual idea documents outrank derived views; respect manual decisions even without companions.
- Ask one focused question only for a consequential ambiguity or missing decision reason. Do not invent evidence, motives or benchmark results.

## Decision Gates
| Condition | Action |
|---|---|
| Missing README, Git or tools | Continue safe analysis; disclose gaps; do not install tools. |
| brainstorm-follow available and not disabled | Use it for authorized reconciliation; retain core fallback if unavailable. |
| Relevant performance hypothesis | Ask about testing the specific idea; invoke brainstorm-perf only after consent. |
| Unsafe path or important contradiction | Preserve state and ask; do not overwrite. |

## Execution Steps
1. Load [analysis](references/project-analysis.md), [idea contract](references/idea-contract.md) and [decisions](references/decision-workflow.md).
2. Identify project purpose and functional capabilities from evidence. Reconcile previous ideas before proposing; present the panorama, not a mandatory prioritization questionnaire.
3. Select domain-coherent proposals within the contract's limits; explain their natural connection, viability and tangible scope.
4. Create a collision-free session, stable IDs and localized documents using the templates. Synchronize affected historical summaries and the global index without rewriting human rationale.
5. Read back files, check links/IDs and report output paths, limitations and any meaningful optional perf check. Do not execute tests as part of generation.

## Output Contract
Produce `brainstorming/index.md`, a dated session `summary.md` and one detail document per new idea. Keep zero-idea sessions honest. Use [index](assets/index.template.md), [summary](assets/summary.template.md) and [idea](assets/idea.template.md) templates.
